\* `completion_tokens` 含**思考 token**。qwen 实际只写 959 字符/150 词，但计费报了 3462 token——这是思考过程计入 completion，**不是过度生成**。已用 `max_tokens=24` 复测确认可见输出被正常截断。

### 5.2 限流：当前目录与真实 429 均为 3 rpm

**2026-11-17 当前公开目录与真实调用**：两个免费模型均标为 `freeRpm: 3`，模型页原文为 `Free model: rate limited to 3 requests per minute per user.`；实际请求也已拿到真实 429，确认不是仅目录声明。

```text
当前真实响应：
HTTP 429
{"error":{"code":"rate_limit_exceeded","message":"Rate limit exceeded: free model glm-5.3-flash-free allows at most 3 requests per minute per user. (request id: ...)",...}}

2026-10-19 历史实测：
HTTP 429
"Rate limit exceeded: free model <id> allows at most 10 requests per minute per user."
```

2026-10-19 突发 14 次调用：第 1–7 次 200，**第 8 次起全部 429**，当时每模型每用户 10 rpm。2026-11-17 的当前免费模型实测中，连续请求已返回 429，响应含真实 `rate_limit_exceeded` code、模型 ID、3 rpm 与 request id；`glm-5.3-flash-free` 4 并发测试出现 2 个 200、2 个异常，说明短窗内并发仍会撞限流/上游瞬时错误，不能当作稳定批量通道。

> 对 ai-proxy 的含义：多模型应按各自额度并行，**同一免费模型不能跑批**；滑动窗口应按目录中的 `freeRpm` 动态取值（当前为 3），不要硬编码旧的 10。

### 5.3 计费面：当前为预付费按量，旧数据仅属历史

**2026-11-17 当前商业规则与账单实测**：

- 官网当前为预付费、按量计费：`Pay only for what you use. One balance for every model. No subscription.`
- 计费单位按模型区分：每 1M token（输入/输出/缓存）或每请求；公开模型页可直接给出单价。
- `1 credit = $1.00 = 26,000 ₫`；余额不过期。公开页面还展示 VietQR、兑换码，以及 USDT/卡片等入口状态，支付可用性应以下单页实时状态为准。
- 当前两个免费模型标为 `$0/request`；其余 5 个旧测评 ID 已变成付费模型，不能继续按“免费无限额度”理解。
- 有效 key 查询 `GET /v1/models` 返回 **200，共 99 个模型**（包含 `deepseek-v3.2`、`glm-5.3-flash-free`）；`billing/subscription` 返回 200，`billing/usage` 的 `total_usage: 0`。

**2026-10-19 历史探测**（旧跑分时的快照）：

- `GET /v1/dashboard/billing/subscription` → 200，`soft_limit_usd: 1e8`（等同无限）
- `GET /v1/dashboard/billing/usage` → `total_usage: 0`
- 当时免费模型不计费；`max_tokens` 超限、`max_tokens=0` 都被**静默接受**（不报错，按默认值跑）

### 5.4 错误面（含 2026-11-17 有效 key 实测）

| 输入 | 上游返回 | OpenAI 规范 | 影响 |
|---|---|---|---|
| 不存在的模型 | **403** + "This token has no access to model X" | 404 | 代理无法区分"没权限"和"没这个模型" |
| 无效 API key | 401 "Invalid token" | 401 | ✅ 一致 |
| `messages: []` | 400 "field messages is required" | 400 | ✅ 一致 |
| `max_tokens: 0` | **200 正常作答** | 400 | 静默忽略参数 |
| `max_tokens: 1e8` | **200 正常作答** | 400 | 静默截到模型上限 |

2026-11-17 无 key/错误 key 实测返回 401 `Invalid token`；用去掉误拼尾部 `key` 后的有效值查询模型列表为 200。当前官方文档同时把 403 解释为“key/group 无权、余额或 key 预算不足”，所以 `403 → 无权限` 不是稳定的“模型不存在”语义。必须结合 404、模型目录和错误文案分类，不能只认状态码。

当前图片测试还发现格式差异：`deepseek-v3.2` 首次接收 SVG data URL 时返回 200 但正文称格式不可识别；改用 PNG 四色块后返回 200 且正确输出“红色，绿色，蓝色，黄色”。`glm-5.3-flash-free` 接收 PNG 后也正确输出“红色、绿色、蓝色、黄色”，但同一 SVG 载荷曾返回 400/`11135`，所以图片必须至少按 PNG/JPEG 交付，不能假定任意 data URL 都能解析。

## 8. 测评的局限（必读）

**qwen3.8-flash 拿了 42.5/42.5 满分，这恰恰说明测试套件饱和了**，而不是它无可挑剔。本套件没有覆盖：

- **长程 agent 任务**（多轮工具编排 + 状态纠错，本次只测了单轮回环）
- **真实代码库修改**（SWE-bench 类，只测了单函数题）
- **超长输出一致性**（只测了 400 字短文）
- **多模态细粒度**（只测了色块，未测 OCR / 图表理解 / 空间关系）
- **数学竞赛级**（只到 GSM8K 难度）
- **中英混杂 / 方言 / 低资源语言**
- **对抗性安全**（只测了 3 个基础拒绝）

另外样本量也有限：能力矩阵每项**只跑 1 次**（逻辑题 3 次），单次结果不能排除偶发。要拿来做严肃选型，应把争议项（B4、D4、视觉）各跑 5–10 次。

## 9. 给 ai-proxy 的接入结论

1. **凭据先到位**：用户提供的 key 在去掉误拼尾部 `key` 后可用；任何自调用/探针必须使用本进程能接受的真实凭据，且 key 不写入仓库、不在日志回显。
2. **只发布当前实测能力**：两个当前免费模型已覆盖非流式/流式、JSON、单工具、PNG 视觉、`max_tokens`/`stop`/`temperature` 与真实 429；身份、长上下文、并行工具、细粒度视觉和完整 30 项矩阵仍未完成，付费模型也未测。
3. **按模型动态限流**：按公开目录 `freeRpm` 实现每模型滑动窗口，当前为 3 rpm；不要硬编码 10 rpm。429 响应已确认带真实 `rate_limit_exceeded`、模型 ID、3 rpm 和 request id，应按文案分类。
4. **计费按目录取模**：按 token 与按 request 的计费单位不同，且价格会漂；成本估算必须从模型页/目录按请求当时快照读取，不要用旧的“免费无限额度”假设。
5. **端点按模型路由**：OpenAI Chat 是基础入口；`/v1/responses`、`/v1/messages` 必须依据每个模型的 `Compatible APIs` 开关。旧 `/v1/completions` 和 `/v1/embeddings` 本次未复测，保持未验证。
6. **错误分类别依赖单一状态码**：无效 key 当前仍为 401；403 可能是无权、余额或预算不足；不存在模型的历史响应是 403 而非 404，需联合文案与目录判断。
7. **重试不能盲发**：历史约 5% 是 `fetch failed`，可安全重试；HTTP 400/401/403 与业务 429 必须分类处理，429 按 `Retry-After` 或指数退避，禁止把确定性鉴权/参数错误当传输抖动重放。本次 429 未给 `Retry-After`，本地滑动窗口仍是必要条件。
8. **视觉和参数能力必须显式标注**：不要从模型名猜测 `inputModalities`、`max_tokens`、`stop` 或 reasoning 行为；已确认 `glm-5.3-flash-free` 忽略 `stop`，PNG 视觉可用但 SVG 不是可靠载荷。
