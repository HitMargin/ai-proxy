**③ 指令遵循差异明显**
- `D2_no_e`（英文句子禁用字母 e）：deepseek-v4-flash 失败（"Bright sun shines, sky is fully bright" 含 e）

- `D4_multi_constraint`（负约束"不能包含 Java"）：glm-5.1 和 glm-5.3-flash **都输出了 JavaScript**——两个智谱模型都在负约束上栽了同样的坑
- `A4_summary_len`（≤40 字）：glm-5.3-flash 交 47 字

**④ 上下文：5 个全部撑住 ~256k token 针检索**
在 96 万字符（≈25 万 token）的填充文本中部埋一个编号，5 个模型全部准确捞出。这是本次最省心的维度。

**⑤ 防幻觉与注入：5 个全过**

- 数据区提示注入 → 全部只输出真实字段，未被劫持
- 系统提示泄漏 → 全部按规则回答"恕难从命"
- 危险请求 → 全部拒绝且未给出配方；正常请求未被误拒

## 4. 多模态：两家是"假的"

用 2×2 四色块图（左上红/右上绿/左下蓝/右下黄）做**不可猜**测试：

| 模型 | 结果 | 判定 |
|---|---|---|
| deepseek-v4-flash | "红色，绿色，蓝色，黄色" ×2 | ✅ **真视觉** |
| deepseek-v4.1-flash | 同上 ×2 | ✅ **真视觉** |
| qwen3.8-flash | "红,绿,蓝,黄" ×2 | ✅ **真视觉** |
| glm-5.1 | "我没有看到您发送的图片" ×2 | ❌ **非多模态** |
| glm-5.3-flash | "目前无法查看图像内容" ×2 | ❌ **非多模态** |

**踩坑记录**：初测用 1×1 纯红图，deepseek 答"粉色"（错），glm-5.1 反问"没看到图"，glm-5.3 说"无法查看"。第二次用 128px 纯蓝图时 glm-5.1 却 3/3 答"blue"——**这是个假阳性**。四色块一测立刻现形：它看不到图，纯蓝图那三次是碰巧/启发式。**教训：视觉能力必须用不可猜的判别性图像测，单色图会被蒙对。**

## 5. 工程指标

### 5.1 吞吐（流式，要求 150 词英文段落）

| 模型 | TTFT | 总耗时 | 输出 token | 有效吞吐 |
|---|---|---|---|---|
| qwen3.8-flash | **1.09 s** | 58.6 s | 4273* | 74 tok/s |
| deepseek-v4.1-flash | 3.40 s | 4.6 s | 180 | **150 tok/s** |
| deepseek-v4-flash | 3.47 s | 4.5 s | 159 | **148 tok/s** |
| glm-5.3-flash | 3.53 s | 6.2 s | 172 | 64 tok/s |
| glm-5.1 | 4.24 s | 23.5 s | 2625* | 136 tok/s |

\* `completion_tokens` 含**思考 token**。qwen 实际只写 959 字符/150 词，但计费报了 3462 token——这是思考过程计入 completion，**不是过度生成**。已用 `max_tokens=24` 复测确认可见输出被正常截断。

### 5.2 限流（硬约束）

```
HTTP 429
"Rate limit exceeded: free model <id> allows at most 10 requests per minute per user."
```

突发 14 次调用：第 1–7 次 200，**第 8 次起全部 429**。之前 8 并发的测试也是 7 个 429 + 1 个 200。**每模型每用户 10 rpm，硬顶，无阶梯豁免**。

> 对 ai-proxy 的含义：多模型可以并行（各自独立额度），但**同一模型不能并发跑批**。DSH 会话中单个模型连续 10 轮以上长对话会撞墙——建议在代理层加「每模型滑动窗口」或做模型轮换。

### 5.3 计费面

- `GET /v1/dashboard/billing/subscription` → 200，`soft_limit_usd: 1e8`（等同无限）
- `GET /v1/dashboard/billing/usage` → `total_usage: 0`
- 免费模型不计费；`max_tokens` 超限、`max_tokens=0` 都被**静默接受**（不报错，按默认值跑）

### 5.4 错误面（与 OpenAI 规范的偏差，会影响代理分类）

| 输入 | 上游返回 | OpenAI 规范 | 影响 |
|---|---|---|---|
| 不存在的模型 | **403** + "This token has no access to model X" | 404 | 代理无法区分"没权限"和"没这个模型" |
| 无效 API key | 401 "Invalid token" | 401 | ✅ 一致 |
| `messages: []` | 400 "field messages is required" | 400 | ✅ 一致 |
| `max_tokens: 0` | **200 正常作答** | 400 | 静默忽略参数 |
| `max_tokens: 1e8` | **200 正常作答** | 400 | 静默截到模型上限 |

## 6. 各模型的"性格差异"

### `max_tokens` 是否真的生效（问 300 字文章，限 24 token）

| 模型 | completion_tokens | finish_reason | 是否遵守 |
|---|---|---|---|
| deepseek-v4-flash | 24 | `length` | ✅ |
| deepseek-v4.1-flash | 24 | `length` | ✅ |
| glm-5.3-flash | 24 | `length` | ✅ |
| qwen3.8-flash | 77（思考 49 + 正文 28） | `length` | ⚠️ 思考不占正文额度 |
| **glm-5.1** | **459**（思考 264 + 正文 195） | `stop` | ❌ **完全忽略** |

**glm-5.1 无视 `max_tokens`**——设 24 给出 459 token。要控成本必须靠 prompt 而不是参数。

### `stop` 序列是否生效（`stop: ["5"]`，从 1 数到 10）

| 模型 | 输出 | 是否遵守 |
|---|---|---|
| glm-5.1 | `1, 2, 3, 4,` | ✅ |
| qwen3.8-flash | `1,2,3,4,` | ✅ |
| deepseek-v4-flash | `1, 2, 3, 4, 5, …, 10` | ❌ |
| deepseek-v4.1-flash | `1, 2, 3, 4, 5, …, 10` | ❌ |
| glm-5.3-flash | `1, 2, 3, 4, 5, …, 10` | ❌ |

3/5 忽略 `stop`。依赖 stop 截断的成本优化在这些模型上会失效。

### `temperature=0` 是否确定

同提示词跑 3 次：

| 模型 | 3 次结果 | 判定 |

| glm-5.1 | 首都是北京 / 首都是北京 / 首都是北京 | ✅ 确定 |
| qwen3.8-flash | 首都是北京 ×3 | ✅ 确定 |
| deepseek-v4-flash | 北京在中国 / 北京是首都 / 北京在中国。 | ❌ 不确定 |
| deepseek-v4.1-flash | 北京是首都 / 北京在中国。 / 北京在中国。 | ❌ 不确定 |
| glm-5.3-flash | （空） / 中国的北京 / 北京 | ❌ 不确定 |

## 8. 测评的局限（必读）

**qwen3.8-flash 拿了 42.5/42.5 满分，这恰恰说明测试套件饱和了**，而不是它无可挑剔。本套件没有覆盖：

- **长程 agent 任务**（多轮工具编排 + 状态纠错，本次只测了单轮回环）
- **真实代码库修改**（SWE-bench 类，只测了单函数题）
- **超长输出一致性**（只测了 400 字短文）
- **多模态细粒度**（只测了色块，未测 OCR / 图表理解 / 空间关系）
- **数学竞赛级**（只到 GSM8K 难度）
- **中英混杂 / 方言 / 低资源语言**
- **对抗性安全**（只测了 3 个基础拒绝）

另外样本量也有限：能力矩阵每项**只跑 1 次**（逻辑题 3 次），单次结果不能排除偶发。要拿来做严肃选型，应把争议项（B4、D4、视觉）各跑 5–10 次。

## 9. 给 ai-proxy 的接入结论

1. **可直接作为 `custom` 供应商接入**——OpenAI Chat 兼容完整，三套端点齐全。
2. **必须在代理层加每模型 10 rpm 限流**，否则 DSH 长会话会成片 429（且 429 消息里已写明限额，可解析）。
3. **`max_tokens` 不可信**：glm-5.1 直接忽略，qwen 的思考不占额度。依赖 `clampOutputBudget` 的逻辑对这两个模型会算错。
4. **`stop` 序列 3/5 失效**，不要用它做成本控制。
5. **错误分类要改**：不存在的模型返回 403 而非 404，现有"403 → 无权限"的映射会误判。
6. **连接重置需要重试**：约 5% 的 `fetch failed` 是传输层抖动，不是上游拒绝。
7. **视觉路由**：只有 deepseek 两个 + qwen 三个可传图；给 glm 两个传 `image_url` 会得到"我看不到图"的软失败（而非 400），**不会报错但会答非所问**——这是最危险的一种失败，必须在模型元数据里标 `inputModalities` 排除。
